# AUDIOBOOK STUDIO — PERMANENT COLOR-FIRST PRODUCTION CONTRACT
Owner directive, 8 November 2026. Applies to ALL current/future original audiobook stories, illustrations, panels, thumbnails, videos and revisions. Read before older project art/video directions. Current owner's explicit instruction overrides older defaults. Preserve all unaffected 109 master writing/source rules and each approved novel's canon.

## Absolute artwork rule
- NEVER generate or deliver black-and-white, grayscale, or monochrome images, including drafts, prototypes, references, manga pages, thumbnails, covers and episodes. Use professionally COLORED original 2D artwork FROM THE FIRST GENERATION. Black outlines and screentones are allowed only inside genuinely colored images. The output must be visibly colored, not gray with a tiny blue effect.
- Each story has a consistent chosen palette and design language, stable cast, costumes, objects, lighting and architectural world rules. Different stories may use different full-color drawing styles: not every picture must resemble manga. Never insert unrelated suited characters, incompatible cyberpunk, invented events, duplicate people or a different novel's world.
- For a request to ONLY ADD COLOR TO APPROVED DRAWINGS, edit pixel color without moving/redrawing a single object, line, face, panel border or pose. Keep the source black-and-white file archived for previously approved work; never generate grayscale art as a NEW step. Do not use a generative redraw model for an exact color-only edit.

## Reusable efficient story-to-video process
1. Read and preserve the latest approved entire story bible/manuscript, current episode spoken script, voice/pronunciation, character/color references, scene plan and prior cached assets. Do not invent continuity or regenerate approved existing narration, including the established Kokoro audio.
2. Make the CURRENT authorized episode, not an unnecessary whole-novel image batch. Story-wide planning stays, but former full-story-illustration-first prerequisite is superseded. Reuse stable character reference, scenery and color palette across episodes.
3. Generate source-accurate FULL-COLOR illustrated pages in batches; typically 2–4 independent legible panels on a page, plus widescreen compositions when a scene needs them. There is NO fixed picture count or forced 5–8-second changes. The old ~180–288 separate images/24 minutes and 10-second still cap are superseded. Select scene changes from actual narration and story beat meaning. Crop each panel separately to 16:9 for the video. Reuse a panel later when actually relevant, but never repeat adjacent frames to fake new footage.
4. Bind each video shot to EXACT approved spoken source excerpt and SHA-256, story/episode/page/panel ID, panel image SHA-256 and real narration duration. Source excerpts concatenated in timeline order MUST equal complete episode spoken script. Never pad or skip speech.
5. Internally examine actual pixels and source for story match, character identity, period/flashback, geography, props, age, injury, powers, rights and image legibility. A color/hash check is not a semantic art review. Generated art is already owner-preapproved for creation, not automatically proven story-accurate or permission to publish. Do not spam art previews into chat; store private assets in Google Drive when technically supported.
6. Build with the existing CPU FFmpeg assembler, 1920x1080 H.264 24fps AAC MP4, using saved Kokoro audio and source-hashed timed panels. The NEW production CLI default is full_color_panels. It must block grayscale, missing/tampered art, mismatched spoken script, mismatched timing and consecutive duplicated frames. Legacy dense mode is historical only, not a choice for new outputs.
7. Cache all assets, render once after preflight and scene QA, upload privately if transfer works and verify real download. Never claim a video is in Drive if the connector cannot upload it. Never publish to YouTube without explicit owner consent.
8. Treat cost and speed as essential. Prefer one small preflight then batch production; reuse approved images/audio, targeted retakes, no repeated full exports, no unnecessary GPU research or extra setup. Record actual end-to-end wall time plus separate image, TTS, editing, rendering, QA, upload, and paid credit/data costs. A one-hour-plus workload for 20 minutes of finished video is a problem to optimize, not a standard to repeat. Never invent cost/time claims.

## Repo enforcement
- color_panel_policy.py checks REAL colored image pixels, script/source hashes, ordered coverage, panel/page and story IDs, timing and duplicate-adjacent frames.
- assemble_existing.py defaults to full_color_panels when invoked as CLI and requires --source-text, --timeline and --audio to build an episode. The only old-mode switch is legacy_dense for archive reproduction.
- test_color_panel_policy.py is synthetic-only regression test suite. GitHub workflow manhua-color-first-tests.yml runs it.
- Story content, private manuscript, images, bibles, narration and production secrets NEVER belong in public GitHub.
- Keep final owner-release gate, rights check, original story master writing standard and full-audio and picture/story inspection. Technical tests do not certify audience appeal or monetization.
